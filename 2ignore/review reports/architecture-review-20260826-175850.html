Problem

"Never label Tier 2 gaps as optimality gaps" is the project's sharpest invariant and it exists only as prose in PLAN §5 and the handover.

Solution

One declarative table of families: generator arguments, seeds, budget, tier — and the tier selects the gap function.

Wins

  • Leverage: one table drives generation and grading

Phase 4 measured the exact solver at 0.10 s for |N|=16 and 0.18 s for |N|=18, and found Tier 1 gaps of exactly 0.00% for all three methods at 20×12. The tiny family is worth widening to |N|=18 in the same table edit — it is the only lever that makes Tier 1 say anything.

6. Resolve the TourCache claim

Speculative in-process

Problem

The module documents leverage it does not have: one of three heuristics uses it, and Phase 5 equalises wall-clock, so a re-route costs iterations rather than nothing.

Solution

Either wire the cache into H1's restart loop, or narrow the claim to H3. Measure first — H2 moves by incremental insertion delta rather than re-routing, so the cache may have nothing to give it.

Wins
  • Claim matches implementation
  • If it lands: more restarts per second
Hard constraint: wiring the cache in changes every number in PLAN §8's tuning table and every result the campaign produces. Do it before the campaign or not at all — never between families.

Deliberately left alone

tsp.py · cover.py · solution.py

Deep already: narrow interfaces over real implementations, and the heaviest-tested modules in the project (128 / 44 / 37). The deletion test fails on all three — removing any concentrates nothing, it just deletes work.

instance.py · exact.py · bounds.py

Interfaces are small relative to what sits behind them — a rejection-sampling generator, a pruned minimal-cover enumeration, a labelled gap type. Only exact.py's dead instance argument (candidate 1) and BestKnown's missing load seam (candidate 5) are in scope.

top recommendation

Collapse (instance, geom) into one case handle

It is the only candidate whose cost strictly grows if deferred. Sixty-nine call sites today, all held by a green suite; after Phase 5 the driver, the record module and the figures add their own. The change is mechanical, and it hands the campaign the instance identity it needs for the best-known registry instead of making it carry a third object alongside.

Then candidate 3 and candidate 4 as Phase 5's opening move — both are modules Phase 5 has to write regardless, so choosing their shape now is free. Candidate 2 is a pure move and can ride along in any commit.
