    feat(exact): Tier 1 ground truth by minimal-cover enumeration
    
    Without a solver there is no LP relaxation and no Lagrangian bound, so the only
    honest way to say "optimal" is to compute it: enumerate covers, route each one
    exactly, keep the best.  Three facts make that finite enough to be worth doing.
    Adding a stop can never shorten a tour, so only minimal covers can be optimal.
    Branching on the most constrained uncovered child, with each branch forbidding
    the options earlier branches took, partitions the space — every minimal cover is
    generated, and none twice, so no memo table is needed at all.  And a spanning
    tree over the stops already chosen lower-bounds every tour through any superset
    of them, which prunes a partial cover the moment its tree passes the incumbent.
    
    This is evaluation infrastructure, not a fourth resolution method, and the
    report must say so.
    
    Trusting it required checking it three ways rather than one.  It agrees with an
    exhaustive subset-times-permutation search that shares none of its reasoning; it
    reproduces a six-child instance whose optimum is 12 + 6*sqrt(2) on paper; and
    across twenty seeded instances no heuristic ever beats it.  That last one is the
    most valuable test in the suite and it is not vacuous — the plain greedy is
    strictly above the optimum on five of the twenty, tabu on three — so the
    inequality is constraining something real rather than holding by luck.
    
    The hand instance is six stops, not the five PLAN.md §7 sketched: the spec
    requires three stops within epsilon of every child, so two separated clusters
    need three stops each and five is geometrically impossible.
    
    max_stops is refused above the Held-Karp cap.  Raising it further would let the
    search reach a cover it could only route heuristically, and an exact search that
    silently falls back to a heuristic route is the one failure that would poison
    every number downstream.

    feat(memetic): H3, memetic algorithm with repair-based crossover
    
    Recombining two covers gene by gene almost always yields something that is not
    a cover — that is the normal case here, not an edge case — so a repair operator
    sits between crossover and evaluation: greedily add stops until every child is
    covered, then drop what recombination made redundant.  Without it selection
    spends the whole budget rediscovering feasibility instead of improving tours.
    
    What makes it memetic is that a share of the offspring are driven to a VND
    local optimum and their improved chromosome is written back, so the population
    searches the space of local optima rather than the far larger space of covers.
    Fitness goes through TourCache: many distinct subsets recur across generations,
    and unlike the trajectory methods nothing here needs a tour that stays monotone
    under node deletion.
    
    Every incumbent is polished at capture rather than once at the end.  Polishing
    is not order-preserving, so a better raw incumbent can polish to a worse tour
    than a weaker one — deferring it would forfeit the guarantee that a longer run
    is never worse than a shorter one.
    
    tests/test_memetic.py::test_repair_preserves_an_already_minimal_cover asserted
    its premise wrongly: it built its "minimal" cover from the alpha=0 greedy, which
    on that fixture leaves five of nine stops removable, contradicting the adjacent
    test demanding repair always return an irredundant cover.  The setup now prunes
    the cover first and asserts that it did, per the PLAN.md §0 rule that a wrong
    test is fixed deliberately and on the record.

Author: TheMonadGuy <enrico.albertini.2001@outlook.it>

    feat(grasp): H1, GRASP with Variable Neighbourhood Descent
    
    Each restart builds a solution with a randomised route-aware greedy, drives it
    to a local optimum with VND, and keeps the best. Alpha is chosen reactively:
    values that have produced good solutions get sampled more often.
    
    Candidates are scored by children newly covered per unit of insertion cost, so
    the construction is aware of the tour it is building. Scoring by coverage alone
    - the classic greedy set cover - optimises the wrong objective: the goal is a
    short route, and six clustered stops can beat four scattered ones.
    
    The unit of work is a Working solution carrying its served set, its tour and
    that tour's length together. This replaces an earlier set-based design that
    scored candidates by re-routing through TourCache, which could not honour the
    "never lengthens" contract: dropping a stop is only guaranteed non-increasing
    for an optimal tour, and re-running nearest-neighbour on the smaller set is not
    monotone. Editing a carried tour is, by the triangle inequality.
    
    VND orders its neighbourhoods by cost - reorder the tour, drop redundant stops,
    then swap - and any success restarts from the cheapest, so expensive moves are
    only tried when nothing cheaper is left. Swaps preserve coverage exactly by
    intersecting the option sets of the children that depended solely on the
    departing stop, so no infeasible candidate is ever evaluated. Termination is
    guaranteed: swaps strictly shorten the tour, the others never lengthen it.
    
    The first restart always uses alpha=0, a deterministic pure greedy, so the
    result can never be worse than the plain constructive heuristic however the
    randomised restarts turn out.
    
    Measured against that greedy baseline at a 2s budget: 8.6% shorter on 30x15,
    13.4% on 120x45, 26.4% on 300x100.
    
    44 tests.

    feat(cover): incremental coverage bookkeeping
    
    Every heuristic searches over subsets of stops, adding and dropping one at a
    time. Recomputing "is every child still covered?" from scratch would be O(|B|)
    per move and dominate the runtime, so CoverState maintains a per-child coverage
    degree and updates it in time proportional to the children near the stop that
    moved.
    
    The removable test built on that degree is the workhorse of the project: a stop
    is removable exactly when every child it covers has degree >= 2. Because adding
    a stop can never shorten a tour under the triangle inequality, an optimal
    solution never serves a redundant stop, so dropping removable stops is an
    always-safe improvement move.
    
    drop() deliberately allows the state to become infeasible - Tabu Search relies
    on crossing infeasible ground - so coverage is the caller's responsibility.
    
    44 tests. The decisive one is the equivalence check: after any random sequence
    of adds and drops, the incrementally maintained degrees must equal a from-scratch
    recomputation. CoverState trades correctness-by-construction for speed, and
    everything downstream trusts that invariant, so it is verified directly rather
    than assumed.

    Constructive heuristics (nearest neighbour, cheapest insertion), local search
    (2-opt and Or-opt), and an exact Held-Karp DP. Nothing here knows about children
    or coverage: it works on a node subset and a distance matrix, so the same code
    routes candidates inside every heuristic and inside the exact reference solver.
    
    A tour is a list of nodes whose first element is always the school, with the
    return leg implicit. Pinning the depot at position 0 costs nothing, since a
    cycle rotates freely, and lets local search skip any move that would displace it.
    
    2-opt scans all partners for a given i in one vectorised numpy expression rather
    than using don't-look bits. The bits are conventionally held per city, but every
    2-opt move reverses a segment and renumbers positions, so keeping them correct
    needs a position-lookup table and is a classic source of subtle bugs. The
    vectorised sweep gets most of the speed-up at these tour sizes with far less to
    go wrong.
    
    Held-Karp performs each mask's transition as a single (k,k) min-plus reduction
    instead of a Python double loop, which is the difference between a second and a
    minute at k=15.
    
    128 tests: exact oracles (a unit square's optimum is 4.0, five collinear points
    give 8.0), agreement with brute-force permutation for small n, and the
    invariants that must hold for any input - local search never lengthens a tour,
    never loses a node, never moves the depot, and never beats the exact optimum.

    convention used by the whole package: stops occupy 0..n_stops-1 and the school
    sits at n_stops, so a stop id and its node id are the same integer.
    
    The generator enforces the specification's structural requirement by
    construction rather than by filtering afterwards. Stops are placed first
    (uniformly, or in Gaussian clusters to mimic residential districts), then each
    child is drawn inside a viable anchor stop's epsilon-disc and kept only if at
    least three stops end up in range.
    
    Anchor viability uses the necessary condition that three stops covering a common
    point lie pairwise within 2*epsilon. It is deliberately not treated as
    sufficient - three stops on an equilateral triangle of side 2*epsilon have
    circumradius 2*epsilon/sqrt(3) > epsilon and cover no common point - so
    rejection sampling still does the real work; the test is only there to prune
    hopeless anchors in sparse clusters.
    
    suggest_epsilon inverts the expected-stops-in-a-disc formula so default radii
    sit comfortably above the 3-stop threshold and sampling stays cheap.
    
    43 tests: the 3-stop property across sizes, seeds and both layouts; determinism;
    JSON round-trips; and the failure paths, each with a hand-checkable oracle.

    docs: design plan, mathematical model, and mandatory TDD policy
    
    PLAN.md is the single source of truth for the project and doubles as the design
    record the written report is lifted from. It fixes the decisions that shape all
    the code that follows:
    
    - The model (variables y/x/z, objective, constraints) is written up but never
      handed to a solver: all three resolution methods are heuristics, which is
      stricter than the course rules allow.
    - With no bus capacity constraint the child assignment is not a real decision,
      so the search space collapses to "pick a covering subset of stops, then order
      it" - a Covering Tour Problem. The triangle inequality then makes any optimal
      stop set a minimal cover, which every heuristic exploits as a free cleanup.
    - Three methodologically distinct heuristics, one per group member: GRASP+VND,
      Tabu Search, and a Memetic Algorithm.
    - Optimality can still be measured without an ILP solver, but only in two
      honest tiers: true optima from hand-written combinatorial search on small
      instances, and gap-to-best-known everywhere else.
    
    Section 0 makes test-driven development mandatory and governs every later
    section: test first, watch it fail, implement, watch it pass, and only then use
    the routine. Tests are never weakened to reach green.
